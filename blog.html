这篇记录本次实验做了什么、中间卡在哪里、最后怎么确认结果。实验要求写在实验指导里：做一个主题明确的网页、发布一篇新博客、检查网页使用的 HTTP 协议版本，页面里要有图片和至少三个超链接。

2. 用 Git 提交并部署到 GitHub Pages

git init -b main
git add .
git commit -m "add lab 1 webpage"
git remote add origin https://github.com/A1exthegreat/my-web-home.git
git push -u origin main

推上去之后网页并不会自动有网站，还要在仓库的 Settings → Pages 里指定用哪个分支发布。我是用命令行做的：

gh api -X POST repos/A1exthegreat/my-web-home/pages \
    -f "source[branch]=main" -f "source[path]=/"

之后每次改完页面，重复三步就能更新：

git add -A
git commit -m "改了什么写清楚"
git push origin main

3. 检查 HTTP 协议版本

按指导书的做法，打开已经发布的页面，按 F12 打开开发者工具，切到 Network（网络）面板，刷新页面，在表头上勾选 Protocol（协议）这一列。主文档那一行显示的是 h2，也就是 HTTP/2。页面里的照片和样式表同样是 h2。

我在命令行里又查了一遍，结论一致：

$ curl -sS -o /dev/null -w "%{http_version}\n" \
    https://a1exthegreat.github.io/my-web-home/
2

$ curl -v -I https://a1exthegreat.github.io/my-web-home/ 2>&1 | grep -E "ALPN|HTTP/"
* ALPN: curl offers h2,http/1.1
* ALPN: server accepted h2
* using HTTP/2
< HTTP/2 200

$ curl -sS --http1.1 -o /dev/null -w "%{http_version} %{http_code}\n" \
    https://a1exthegreat.github.io/my-web-home/
1.1 200

三条结果说明：协商结果是 HTTP/2；服务端也支持 HTTP/1.1，客户端不报 h2 时会退回 1.1；页面本身没有宣告 HTTP/3。

4. 卡住的几个地方

  1. 发布后打开是 404。原因是 Pages 的发布目录设成了 /docs，而我把页面推在仓库根目录。把 source[path] 改成 / 就正常了。
  2. 线上只剩文字，样式丢了。本地用 file:// 打开时一切正常，上线后样式表加载不到。原因是我一开始写的是 /css/style.css，站点挂在 /my-web-home/ 这个子目录下，这个绝对路径指到了站点外面。改成相对路径解决。
  3. 改了页面看不到变化。响应头里有 cache-control: max-age=600，浏览器和中间缓存都还在用旧文件。判断是否发布成功的时候不要只看浏览器，用 curl 看一遍更靠得住。
  4. 把代理的响应当成了网页的协议版本。我的机器上开了本地代理，curl 输出第一行是 HTTP/1.1 200 Connection established，这是代理为建立隧道回的响应，不是网页的版本号。真正的状态行在它下面一行。
